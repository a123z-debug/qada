# أصول القضاء — QADA

منصة قانونية سعودية متعددة الوكلاء لتحليل القضايا والمستندات وصياغة المذكرات ومراجعتها قبل الإخراج النهائي.

## الإنتاج المعتمد

- المستودع: `a123z-debug/qada`
- الفرع: `master`
- الاستضافة: Railway
- الرابط المعتمد: https://qada-production-5067.up.railway.app/
- التخزين: Redis خاص داخل Railway
- وضع الاختبار العام: مغلق افتراضياً

## بنية الاستخدام

- **Simple**: للمستخدم العادي، يصف المشكلة أو يرفع المستند وتدير المنصة المسار دون إغراقه بالتفاصيل القانونية.
- **Professional**: للتحليل التفصيلي والمراجع والمواد والأدلة.
- **Admin**: لإدارة الوكلاء، السجلات، المصادر، الجاهزية والأخطاء.

## QADA Intelligence Kernel

أضيفت طبقة تنسيق ذكية فوق مسار QADA القانوني لتكوين **فريق قضية ديناميكي** بدل تشغيل مجموعة ثابتة من الوكلاء في كل مرة.

المسار الداخلي الجديد:
`Intake → Route → Legal Truth → Analysis → Red Team → Drafting → Virtual Judge`.

- **Legal Truth Layer** تحمل حالة المصدر الرسمي، المواد المتحققة، قيود التحقق، جاهزية الاقتباس الحرفي، وحالة corpus السوابق.
- **Dynamic Case Team** يختار الوكلاء المناسبة بحسب نوع الطلب ومرحلة الحكم وحالة المصادر والمرفقات.
- **Agent OS Bridge** اختياري ويُستخدم لتخطيط القدرات فقط؛ لا ترسل إليه وقائع القضية الخام أو المرفقات أو المعرّفات الشخصية.
- بوابات QADA القانونية تبقى أعلى سلطة في المجال القانوني، ولا يستطيع Agent OS تجاوز `blocker` أو `Virtual Judge`.
- قيمة `orchestrationConfidence` تقيس اكتمال خطة التشغيل، **ولا تمثل احتمال الفوز بالقضية أو توقع الحكم**.

راجع `QADA_AGENT_OS_ARCHITECTURE.md` للتفاصيل.

## بوابة الجودة القانونية

المخرجات النهائية تمر عبر:
`Court Profile → Case Strategy → Source Verification → Drafting → Red Team → Virtual Judge → Release Gate`.

لا يسمح بإخراج نهائي عندما توجد عوائق جوهرية، والمستهدف الداخلي للجاهزية 99/100 مع حد أدنى 95/100 قبل الاعتماد.

## التشغيل المحلي

المتطلبات: Node.js 22.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

المتغيرات الحقيقية تحفظ في Railway Variables ولا تضاف إلى Git.
